# VALIDATION_PLAN.md — Zeta Harp v2

Purpose: before any visual or audio ships, the implementation of MATH_SPEC.md is checked
against independent references. All checks are computations compared to computations; none
of them certifies a zero and none of them is evidence for RH (CLAIM_BOUNDARY.md).

## Fixture windows (height t)

| Window | Range | Why |
|---|---|---|
| W1 | [100, 160] | Dense hand-checkable window; low-t stress for the theta asymptotic; first fixture for every room |
| W2 | near 10^4 | Mid-range; N(t) ~ 39; typical exhibition window |
| W3 | near 10^6 | N(t) ~ 398; performance and precision stress |
| W4 | near 10^8 | N(t) ~ 3989; float64 phase-accuracy frontier; documents where the instrument's honest range ends |

Each window gets a frozen fixture file (t grid, Z_ref, theta exact, theta asymptotic,
M, R_ref) generated by an mpmath script committed alongside it.

## Zero windows

Reference table: the in-repo Odlyzko-derived table `experiments/zeta_cube_null/zeros1.txt`
(100000 zeros, covering t up to ~75000). Zero-comparison checks therefore run only in
windows W1 and W2 and any additional window below t ~ 75000; W3/W4 zero locations are out
of the table's range and are NOT checked against it (and must not be presented as checked).

Check: for each sign change of M(t) in a zero window, bracket and bisect to a crossing
location, then match to the nearest table zero. Report the offset. Labeling law: ours are
"computed reference crossings" compared against a published table; the comparison validates
our computation, it does not certify zeros.

## Required error metrics

1. **Reconstruction error**: max-abs and RMS of (M(t) + R_ref(t)) - Z_ref(t) over each
   fixture grid. By construction this is a self-consistency check of the pipeline (should
   be at numerical noise); it guards against wiring bugs between M and Z_ref.
2. **Main-sum residual size**: max-abs and RMS of R_ref(t) per window, reported so every
   room can display how large the un-drawn remainder is relative to M(t).
3. **Theta asymptotic error**: max-abs of theta_asymptotic(t) - theta_exact(t) per window
   (theta_exact via mpmath loggamma). Must be below the phase resolution that matters for
   rendering (target: < 1e-6 rad in W1, tighter above).
4. **Crossing offset**: for every matched crossing in the zero windows, |t_crossing -
   t_table|; report max and median per window.
5. **Cutoff-entry consistency**: for each n with t_n = 2*pi*n^2 inside a window, verify
   N(t) increments by exactly 1 at t_n (floor boundary behavior pinned, including the
   equality edge).

## Audio-frequency derivative check

The Truth Audio law says f_audio_n = v_t * (theta'(t) - ln n) / (2*pi). Check that the
closed-form theta'(t) used by the sonifier matches a central finite difference of phi_n:

    | (phi_n(t+h) - phi_n(t-h)) / (2h) - (theta'(t) - ln n) |  <  tol

on each fixture grid (h chosen per window; tol target 1e-8 relative in W1/W2). This pins
the claim "what you hear is the derivative of the phase you see" to a test, per string,
before any audio ships.

## Gate rule

No room renders and no sound plays in a shipped build until the metrics above are computed
for W1 at minimum and recorded in MATHEMATICIAN_NOTE.md's validation summary. W2-W4 results
are appended as they are produced; any window without recorded results is labeled
unvalidated in the UI.
